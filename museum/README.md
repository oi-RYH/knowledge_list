# 빛의 우물과 지식의 은하

`TECH_KNOWLEDGE.md`와 `WORKFLOW_KNOWLEDGE.md`에 쌓인 지식을 거닐며 보고, 끝에서 시험을 치르는 3D 웹입니다. 같은 기록을 두 장소에서 볼 수 있습니다. 바다 위의 탑인 빛의 우물과, 기록이 별로 놓인 지식의 은하입니다. 이 폴더와 저장소 루트의 `index.html`이 전부이며, `web` 브랜치에만 있습니다. `main`은 건드리지 않습니다.

처음에는 길게 뻗은 회랑("지식의 회랑")이었고, 2026-11-11에 지금의 우물로 구성을 바꿨습니다. 회랑은 커밋 `cbffe19`까지의 기록에 남아 있습니다.

## 여는 법

로컬에서 미리 보려면 저장소 루트에서 서버를 띄웁니다. 파일을 직접 더블클릭하면 열리지 않습니다.

```sh
python3 museum/tools/serve.py
```

그다음 브라우저에서 `http://localhost:4173`을 엽니다.

실제 주소는 `https://oi-ryh.github.io/knowledge_list/`입니다. 저장소 설정의 Pages에서 배포 브랜치가 `web`, 폴더가 `/ (root)`로 지정되어 있고, `web`에 푸시하면 1~2분 뒤에 반영됩니다.

## 두 장소 고르기

왼쪽 위에 표시 두 개가 있습니다. 겹친 원이 빛의 우물이고, 나선이 지식의 은하입니다. 다른 쪽을 누르면 화면이 그 장소의 빛(또는 어둠)으로 닫혔다가 그 장소에서 열립니다.

- 고른 장소는 브라우저에 기억됩니다. 다음에 주소만으로 열면 마지막에 고른 장소가 열립니다. 처음 오면 우물입니다.
- 주소에 `?theme=well` 또는 `?theme=galaxy`를 붙이면 그 장소로 바로 엽니다.
- 두 장소는 같은 `index.html`입니다. 페이지 머리의 짧은 스크립트가 장소를 정하고, `museum/js/boot.js`가 그 장소의 코드(`main.js` 또는 `space/main.js`)를 불러옵니다. `space.html`은 `?theme=galaxy`로 넘겨 주기만 합니다.

## 설명 패널

석비나 별에 다가서면 오른쪽에서 패널이 들어와 그 기록을 설명합니다. 전에는 화면 아래에 한 문장이 떴습니다. 패널의 모양은 애플의 인터페이스 방식을 따릅니다.

- 패널이 들어오는 만큼 그림이 왼쪽으로 비켜서, 다가선 기록이 남은 화면의 가운데에 옵니다. 카메라를 돌리는 것이 아니라 보는 창을 옮기는 것이어서 기록을 보는 각도는 그대로입니다.
- 내용은 주제, 이름, 영어 원래 이름, 한 문장 요약, 긴 설명, 기록한 날과 이해 상태, 같은 주제의 다른 기록 순서입니다.
- 긴 설명은 개념이면 무엇인가, 왜 필요한가, 내 작업에서, 기억할 것입니다. 과정이면 무엇을 하는 일인가, 차례, 내 작업에서, 기억할 것입니다.
- 같은 주제의 다른 기록을 누르면 그 기록으로 옮겨 가고, 패널은 닫히지 않은 채 글만 바뀝니다.
- 패널 위에서는 스크롤과 위아래 방향키, Page Up, Page Down, 스페이스가 글을 넘깁니다. 그림 쪽에서 스크롤하거나 Esc를 누르거나 패널의 닫기 단추를 누르면 물러섭니다.
- 좁은 화면(폭 640px 이하)에서는 옆에 자리가 없어서 패널이 아래에서 올라오고, 그림이 위로 비켜섭니다. 이때는 패널 위쪽의 손잡이를 잡아 끌어내릴 수 있습니다. 끄는 동안 패널이 손가락을 그대로 따라오고, 놓으면 그 속도를 이어받아 닫히거나 제자리로 돌아갑니다.
- 패널은 화면 가장자리에서 떨어져 떠 있는 둥근 유리판입니다(글래스모피즘). 뒤의 그림이 흐려진 채 색까지 비쳐 보일 만큼 얇습니다. 장소가 밝으면(우물의 햇빛 드는 곳) 맑은 유리, 어두우면(해수면 아래, 은하) 그을린 유리가 됩니다.
- 유리로 보이게 하는 것은 네 가지입니다. 빛이 오는 쪽에서 밝고 둘레를 돌며 옅어지는 테두리, 위쪽 모서리를 가로지르는 광택, 아래쪽 가장자리 안쪽에 고인 빛, 판을 그림에서 띄우는 그림자입니다.
- 차례와 같은 주제의 목록, 기억할 것, 닫기 단추, 번호 배지도 같은 유리의 더 얇은 판과 구슬입니다.
- 터치 기기에서는 흐림을 줄이고 유리를 조금 더 짙게 합니다. 값은 `museum/museum.css`의 `--p-material`, `--p-glass`, `--p-rim`, `--p-sheen`에 있습니다.
- 패널 안의 글자는 시스템 글꼴입니다(Apple 기기에서는 SF Pro와 Apple SD 산돌고딕 Neo). 패널 밖의 글자는 그대로 Hahmlet입니다.
- 개념은 파란색, 과정은 주황색으로 표시합니다. 차례와 같은 주제의 기록은 둥근 바탕 위의 묶음 목록이고, 기억할 것은 그 색을 옅게 깐 판에 놓입니다.
- 패널은 스프링으로 움직입니다(튀지 않고, 도착까지 0.4초쯤). 들어오는 도중에 물러서면 그 자리에서 그 속도로 되돌아갑니다.
- 운영체제의 투명도 줄이기와 대비 높이기 설정을 따릅니다. 그때는 흐림 없이 불투명한 판이 됩니다.

코드는 `museum/js/panel.js`, 모양은 `museum/museum.css`의 패널 부분입니다.

## 생김새

바다 위에 선 둥근 탑이고, 가운데가 위에서 아래까지 비어 있습니다. 벽 안쪽을 따라 경사로가 나선으로 내려가고, 석비는 그 경사로에서 빈 공간을 바라보고 서 있습니다. 그래서 어디에 서든 맞은편과 위아래 층의 석비가 함께 보입니다.

- 맨 위가 가장 최근에 추가한 기록이고, 내려갈수록 오래된 기록입니다. 오른쪽 점은 추가한 날짜입니다.
- 심판의 존재는 빈 공간 한가운데에서 방문자와 같은 높이로 함께 내려옵니다.
- 위쪽 벽의 아치는 바다로 열려 있어 해가 듭니다. 해수면 아래로 내려가면 아치가 막히고, 존재의 빛만 남습니다.
- 맨 아래 바닥에서 시험을 치릅니다.
- 기록이 20개 늘 때마다 탑이 한 바퀴(6.4m) 높아집니다. 다시 설계할 것은 없습니다.

| 드래그 | 사방을 둘러봅니다. 한 바퀴를 다 돌 수 있고, 위아래로도 거의 끝까지 볼 수 있습니다. 화면을 잡아 끄는 방식이라, 오른쪽으로 끌면 왼쪽이 보입니다. 끌다가 놓으면 조금 더 돌다 멈춥니다 |
| 좌우 방향키, A / D | 30도씩 돌아봅니다 |
| 석비 클릭 | 보이는 석비는 어디에 있든 고를 수 있습니다. 가까우면 걸어가고, 멀면 빈 공간을 가로질러 날아갑니다. 다가가면 천이 벗겨지고, 오른쪽에서 설명 패널이 들어옵니다 |
| Esc / 그림 위에서 다시 스크롤 | 물러섭니다. 패널 위에서의 스크롤은 설명 글을 넘깁니다 |
| 오른쪽 점 | 그 날짜의 자리로 갑니다. 멀면 날아갑니다 (마름모는 시험을 치르는 바닥) |
| Page Down / Page Up | 다음 / 이전 날짜 |
| 바닥에서 1~4 | 보기를 고릅니다 |
| 왼쪽 아래 스피커 | 소리를 켜고 끕니다 (기본은 꺼짐) |

터치 화면에서는 한 손가락으로 위아래로 쓸어 걷고, 좌우로 쓸어 돌아보고, 석비를 눌러 다가갑니다. 두 손가락으로 끌면 위아래까지 사방을 둘러봅니다.

걷는 길은 경사로로 정해져 있고, 시선만 자유롭습니다. 석비 앞에 다가서면 석비를 정면으로 보지만 거기서도 둘러볼 수 있고, 맨 아래 바닥에 들어설 때는 시선이 한 번 존재 쪽으로 모입니다.

## 내용이 들어오는 길

1. 열릴 때 GitHub의 `main`에서 두 기록 파일을 직접 읽습니다. 실패하면 이 브랜치에 있는 사본을 씁니다.
2. `museum/data/exhibit.ko.json`에서 한글 이름, 한 줄 설명, 긴 설명, 퀴즈를 찾아 붙입니다.
3. 여기에 항목이 없는 기록은 영어 이름과 영어 메모로 나오고, 퀴즈에서는 빠집니다.
4. 기록을 추가한 날짜 순으로 위에서부터 세웁니다. 같은 날짜 안에서는 기록 파일의 순서를 따르고, 날짜가 없는 기록은 맨 아래로 갑니다.

푸시하지 않은 로컬 기록은 보이지 않습니다. GitHub에 올라간 것만 보입니다.

### 새 항목의 한글 설명과 퀴즈 추가

`museum/data/exhibit.ko.json`의 `tech` 또는 `workflow`에, 기록 파일의 항목 이름을 그대로 키로 써서 넣습니다. 백틱은 빼도 됩니다.

```json
"Cross Compilation": {
  "ko": "크로스 컴파일",
  "note": "내 컴퓨터에서, 다른 CPU에서 돌아갈 실행 파일을 만드는 일입니다.",
  "detail": {
    "what": "무엇인지를 처음 보는 사람도 알 수 있게 두세 문장으로.",
    "why": "왜 쓰는지, 없으면 무엇이 잘못되는지.",
    "work": "내 작업에서 어땠는지. 기록 파일의 Notes에 있는 사실만 씁니다.",
    "point": "남에게 설명할 때 할 한두 문장."
  },
  "quiz": [
    { "q": "묻는 문장.", "o": ["정답", "오답", "오답", "오답"], "a": 0 }
  ]
}
```

`detail`이 설명 패널에 나오는 긴 설명입니다. 과정(`workflow`) 항목은 `why` 대신 `steps`(차례를 문장의 배열로)를 씁니다. `detail`이 없는 항목은 패널에 한 줄 설명만 나옵니다.

`a`는 정답의 위치(0부터)입니다. 화면에서는 보기 순서가 매번 섞입니다. 새 분야가 생기면 `categories`에 한글 이름도 넣습니다.

빠진 것이 있는지 확인합니다.

```sh
node museum/tools/check-data.mjs
```

다른 폴더의 기록(예: 아직 푸시하지 않은 로컬 사본)으로 확인하려면 폴더를 넘깁니다.

```sh
node museum/tools/check-data.mjs ~/Documents/90-99_Shared-Etc/AI/knowledge_list
```

### 에이전트가 계속 써넣는 방식

`main`의 `AGENTS.md`에 `Museum Entries` 조항이 있습니다. 에이전트는 새 항목을 기록 파일에 등록할 때, 이 브랜치의 `museum/data/exhibit.ko.json`에 한글 이름과 한 줄 설명, 퀴즈 한두 문제를 함께 씁니다. 그 조항은 긴 설명(`detail`)이 생기기 전에 쓴 것이어서 아직 `detail`을 요구하지 않습니다. 조항을 고치기 전까지 에이전트가 새로 넣는 항목에는 긴 설명이 없습니다.

- 전시 데이터는 `web` 브랜치에만 둡니다. `main`에는 조항만 있고 박물관 파일은 없습니다.
- 에이전트는 `web`이 체크아웃된 작업 폴더를 찾아 그 안의 파일을 고칩니다. 이 Mac에서는 이 폴더가 그 작업 폴더입니다. 작업 폴더가 없는 기기에서는 지식 저장소 옆에 `knowledge_list-web`을 새로 만듭니다.
- 에이전트는 커밋이나 푸시를 하지 않습니다. 써넣은 내용은 `web`을 푸시해야 사이트에 반영됩니다.
- 작업 폴더를 못 찾거나 파일을 못 쓰면 건너뛰고 알려 주기만 합니다. 그 항목은 영어 이름으로 나오고 퀴즈에서 빠집니다.

새 기록이 사이트에 다 보이려면 두 브랜치를 모두 푸시해야 합니다. 기록은 `main`, 한글 설명과 퀴즈는 `web`입니다. `web`은 이 폴더에서 올립니다.

```sh
git push origin web
```

## 치수 바꾸기

우물의 치수는 모두 `museum/js/config.js`의 `DIM`에 있습니다. 한 바퀴의 칸 수, 한 바퀴에 내려가는 높이, 벽과 빈 공간의 반지름, 해수면 아래로 잠기는 바퀴 수, 해의 방향을 여기서 바꿉니다. 건물, 걷는 길, 그림자, 반사광이 모두 이 값에서 만들어집니다.

## 물감으로 칠하기

화면은 사진처럼 그대로 내보내지 않고, 유화처럼 붓질로 다시 칠해서 보여 줍니다. 빛과 그림자는 먼저 실제처럼 계산하고, 그 결과를 물감으로 옮깁니다. 2026-11-11에 시험판을 본 뒤 기본 화면으로 채택했습니다.

칠하기 전의 화면(실사)을 보려면 주소에 `?paint=0`을 붙이거나, 보는 중에 `P`를 누릅니다.

칠하는 순서는 세 단계입니다.

1. **화가의 눈.** 칠하기 전에 화면의 색을 다시 봅니다. 해가 드는 곳은 해의 그림자 지도로 정확히 가려내고, 면이 어느 쪽을 보는지는 깊이 정보로 압니다.
   - 햇빛을 받는 흰색은 따뜻하게 둡니다.
   - 그늘은 회색으로 두지 않습니다. 위를 보는 면은 하늘빛(청보라)으로, 아래를 보는 면은 햇빛 받은 바닥에서 되비친 따뜻한 빛으로 칠합니다. 서 있는 면은 하늘빛이 기본이고, 원래 화면이 뚜렷이 따뜻한 곳에서만 따뜻하게 칠합니다.
   - 바다는 멀리 보랏빛 파랑, 가까이 짙은 청록으로, 하늘은 파랑으로 칠합니다. 물마루와 반짝임은 흰색으로 남깁니다.
   - 바다와 하늘은 같은 굵기의 잔붓질로, 가로 방향으로 칠합니다. 색은 붓질마다 제각각이 아니라 긴 가로 띠를 따라 이어집니다. 물결선과 공기층이 그렇게 보이기 때문입니다(바다는 청록에서 보라 사이). 바다의 붓질은 가늘고 하나하나 보이며, 가까운 물에서는 가끔 밝은 붓질이 섞입니다. 하늘의 붓질은 얇게 올려 서로 부드럽게 섞입니다. 물결을 사진처럼 또렷하게 되살리지는 않고, 물의 반짝임만 마지막에 넣습니다. 하늘의 붓질은 수평선 아래로 내려오지 않습니다.
   - 먼 바다는 잔잔하게 칠합니다. 물결이 화면의 한 픽셀보다 작아지는 거리부터는 물결을 그리지 않습니다(`skysea.js`). 그리면 프레임마다 지직거리기 때문입니다.
   - 경사로는 따뜻한 돌색, 벽은 천보다 한 톤 깊게 해서 재질이 서로 갈리게 합니다.
   - 해수면 아래로 내려가면 이 손질을 줄입니다. 거기서는 존재의 빛 색이 곧 말이기 때문입니다.
2. **붓질.** 넓은 면은 큰 붓으로, 경계와 글씨 둘레는 작은 붓으로 칠합니다.
   - 붓질은 화면이 아니라 벽, 경사로, 석비 표면에 붙어 있어서, 걸어도 미끄러지지 않고 다가가면 커집니다.
   - 붓질 하나는 한 사물에만 속합니다. 다른 사물의 색을 가져오지 않고, 윤곽을 넘어가지도 않습니다. 그래서 사물의 경계가 또렷합니다.
   - 햇빛과 그늘의 경계에서도 붓질이 끊깁니다.
3. **캔버스.** 물감의 요철에 빛이 비스듬히 닿고, 얇게 칠한 곳에는 천의 결이 비칩니다. 난간, 물의 반짝임, 글씨의 모서리 같은 것은 마지막에 가는 붓으로 또렷하게 넣습니다.

존재는 칠하지 않습니다. 빛이기 때문입니다. 석비 앞에 다가서면 새긴 글씨를 가는 붓으로 다시 그려 넣어, 이름이 읽히게 합니다.

붓의 크기는 `museum/js/paint.js`의 `stroke`, 요철은 `relief`, 붓질을 칠하는 해상도는 `config.js`의 `QUALITY.*.paint`에서 바꿉니다.

## 지식의 은하

같은 기록을 다른 장소에 놓은 두 번째 장소입니다. 왼쪽 위의 나선 표시로 고르거나 주소에 `?theme=galaxy`를 붙여 엽니다.

- 장소는 나선 은하입니다. 기록 하나하나가 별이고, 같은 주제의 별은 한 성단으로 모여 있습니다. 성단은 은하의 팔 하나를 따라 기록 파일의 주제 순서대로 놓입니다.
- 주제 이름이 같으면 개념(`TECH_KNOWLEDGE.md`)과 절차(`WORKFLOW_KNOWLEDGE.md`)가 한 성단에 들어갑니다.
- 성단마다 별을 잇는 별자리 선이 있고, 그 위에 주제 이름이 빛으로 떠 있습니다. 선은 개념 쪽 끝이 푸르고 절차 쪽 끝이 따뜻합니다. 성단 둘레에는 작은 별이 무리 지어 있어 멀리서도 모임으로 보입니다.
- 새 기록은 제 주제의 성단에 별로 더해지고, 새 주제는 성단을 하나 더해 팔을 길게 합니다. 날짜 순서는 쓰지 않습니다.
- 은하 자체는 기록이 아니라 장소입니다. 막대 모양 중심부, 큰 팔 둘과 그 사이의 작은 팔 둘, 팔 안쪽 가장자리의 어두운 먼지 띠, 결이 있는 색색의 성운, 별이 태어나는 분홍빛 매듭(푸른 어린 별 무리와 함께), 은하를 둘러싼 헤일로와 구상성단으로 이루어집니다. 하늘 멀리에는 비스듬히 보이는 이웃 나선 은하 하나와 작은 불규칙 은하 둘, 그리고 아주 먼 은하들이 있습니다.
- 분홍빛 매듭은 기록이 놓인 팔 구간에는 두지 않습니다. 그 구간에서 별이 모여 있으면 언제나 주제입니다.
- 방문자는 팔 위를 따라 은하 중심 쪽으로 들어가며 성단 위를 차례로 지납니다. 오른쪽 점은 주제이고, 누르면 그 성단이 앞에 다 보이는 자리에 섭니다.
- 이해 상태는 별의 일생으로 보여 줍니다.
  - ❓ 미확인: 아직 불이 붙지 않은 가스 구름. 안에 불씨만 있다가, 다가서면 별로 켜지고 떠나면 다시 구름에 잠깁니다.
  - ⬜ 미학습: 작고 흔들리는 붉은 별
  - 🟡 익숙함: 따뜻하고 고른 별
  - ✅ 이해함: 빛살이 뻗는 크고 푸른 별
- 별에 다가서면 우물과 같은 설명 패널이 들어옵니다.
- 별 이름은 별 아래에 빛으로 쓰이고, 가까이 있는 별과 가리키거나 다가선 별에만 나타납니다. 주제 이름은 앞쪽 성단 서넛까지만 보입니다.
- 팔이 끝나는 은하 중심에서 시험을 치릅니다. 심판은 우물과 같은 존재입니다.
- 조작은 우물과 같습니다(스크롤로 이동, 드래그로 둘러보기, 별 클릭, 오른쪽 점).

파일은 `museum/js/space/`(`main.js`, `layout.js`, `galaxy.js`, `stars.js`)입니다. 치수는 `space/layout.js`의 `SPACE`에 있습니다. 은하의 별 수와 구름 양은 `space/main.js`에서 화질 단계에 따라 `buildGalaxy`에 넘깁니다(`stars`, `rich`).

## 천 다시 굽기

석비 치수를 바꿨을 때만 필요합니다. `steles.js`와 `bake-veil.mjs`의 `SLAB`, `PLINTH`를 같은 값으로 맞춘 뒤 실행합니다. 1분 반쯤 걸립니다.

```sh
node museum/tools/bake-veil.mjs
```

## 주소 옵션

| 옵션 | 뜻 |
|---|---|
| `?order=field` | 날짜 대신 기록 파일의 분야 순서로 세웁니다. 오른쪽 점도 분야가 됩니다 |
| `?paint=0` | 붓질로 칠하지 않고, 카메라가 만든 화면(실사) 그대로 봅니다. 보는 중에 `P` 키로도 바꿀 수 있습니다 |
| `?q=ultra`, `high`, `medium`, `low` | 화질을 고정합니다. 없으면 프레임 속도를 보고 스스로 맞춥니다 |
| `?s=120` | 그만큼 걸어 내려간 자리에서 시작합니다 (미터) |
| `?records=<주소>` | 다른 곳의 기록 파일로 미리 봅니다 |
| `?plain` | 3D 없이 글로만 봅니다 |
| `?gi=1` | 반사광을 한 번만 계산해 더 빨리 엽니다. `?gi=0`은 계산하지 않습니다 |
| `?off=ao,air,bloom,fxaa,grain,mirror` | 화면 효과를 하나씩 끕니다 (점검용). `fxaa`와 `grain`은 실사 화면에만 있습니다 |

## 알아 둘 것

- WebGL2가 안 되는 브라우저에서는 같은 내용이 글 목록으로 나옵니다.
- three.js와 글꼴은 CDN에서 받습니다. 오프라인에서는 열리지 않습니다.
- 열릴 때 반사광을 계산하느라 몇 초가 걸립니다. 화면 아래의 가는 선이 진행 정도입니다.
- 화면이 크거나 그래픽 성능이 낮으면 해상도를 먼저 낮추고, 그래도 느리면 효과를 줄입니다.
- 움직임 줄이기 설정을 켠 기기에서는 걷는 흔들림과 이동 애니메이션을 뺍니다.
- 점검할 때는 콘솔에서 `museum`으로 장면과 상태를 볼 수 있고, `museum.step()`으로 한 프레임씩 그릴 수 있습니다.
